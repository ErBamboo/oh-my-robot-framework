# Boot / OTA 需求分析

> **状态**：v1 定稿（2026-09-14）。开工序列步骤 ②（Bootloader 最小工程）与步骤 ③（OTA 状态机）的需求基线。
>
> **约束锚点**：同目录 `reference_design_notes.md`（`P-xx` 分层定界 / `K-xx` 成熟框架考量）与 `multi_strategy_boot_design.md`（`Q-xx` 拍板记录）。本文件只陈述**需求**；已由决策满足的部分以"编号+slug"引用，不复述决策正文。
>
> **需求来源**：使用场景（竞赛现场灌固件 / app 内在线升级 / 自动回退保障 / 多板多用户泛化）+ 五路源码级实核（K-22..K-29）。
>
> **判据口径**：每条需求带可验证的判据；判据不写实现方式，只写可观察结果。

## 1. 场景与需求

### SC1 竞赛现场灌固件（现场操作手，不拆机、不接调试器）

现场形态：有线串口连接，操作手在赛场环境完成灌写；环境不可控（供电、线缆、时间）。

| 编号 | 需求 | 判据 |
|---|---|---|
| R-DL-1 | 后门**无有效 app 也能进入**并完成一次完整下载 | 两槽镜像均无效时，设备仍能被完整灌入一个可启动镜像 |
| R-DL-2 | 进入方式**不依赖按键/跳线**（仅靠上电时序 + 串口） | 冷启动窗口内收到合法握手帧即进入 |
| R-DL-3 | 断线后可**从已写偏移继续**，不重传整镜像 | 中途断电/拔线后重连，已落盘部分被识别并跳过 |
| R-DL-4 | 连续失败**不产生复位环**（失败必须可见、可诊断） | 校验失败 / 无有效镜像时停留在可交互状态，不反复复位 |
| R-DL-5 | 高危命令需**访问门禁** | 未通过门禁的会话无法执行写入/擦除/跳转 |
| R-DL-6 | 下载过程的**进度可观测** | 每次块传输的响应含已写偏移 |

### SC2 app 内在线升级（下载方为设备自身）

形态：app 内置升级服务，经传输通道接收镜像后写入非活动槽，标 pending，重启生效。

| 编号 | 需求 | 判据 |
|---|---|---|
| R-IMG-1 | 镜像**自描述**：bootloader 无需外部元数据即可判定"是什么、多大、从哪开始、是否完整" | 仅持有镜像副本即可完成全部合法性判定 |
| R-IMG-2 | **版本可比**（含防降级判据） | 拒绝比当前运行版本更旧的镜像（可配） |
| R-SLOT-1 | 写入目标与运行槽**物理隔离** | 下载/写入过程中运行槽内容零改动 |
| R-SLOT-2 | 未标 pending 前**不影响当前启动决策** | 写入中途任意点断电，下次启动仍进入原运行槽 |
| R-SLOT-3 | app 可**自校验**下载结果（不依赖 bootloader） | app 侧能独立算出镜像摘要并与头部摘要比对 |
| R-SLOT-4 | app 可**只读**查询 boot 状态（当前槽、镜像版本、是否待确认） | 有公开查询接口，且 app 无法借此改变启动决策 |
| R-SLOT-5 | app 只能 **confirm**（或什么都不做），无权翻指针 | 无任何 app 可达的接口能改写启动决策字段 |

### SC3 自动回退保障（现场无人干预）

形态：新镜像试运行期未获确认 → 自动回退到上一可用镜像。

| 编号 | 需求 | 判据 |
|---|---|---|
| R-SLOT-6 | 试运行窗口由**可配的启动计数**界定，达限自动回退 | 连续 N 次启动未确认即回退（N 可配） |
| R-SLOT-7 | 计数**掉电保持**（掉电/复位视为一次启动） | 试运行期间断电，重新上电后计数继续推进 |
| R-SLOT-8 | **稳态零写**（已确认的镜像不再产生 flash 写入） | 确认后连续 N 次启动，flash 写次数为 0 |
| R-SLOT-9 | 回退目标**必须先校验**；回退失败不写坏决策 | 另一槽不可用时停在可交互状态，决策数据保持可读 |
| R-SLOT-10 | 回退判定与提交权限**归 bootloader**，与提交策略正交 | 换提交策略不改判定逻辑，换判定不改提交动作（ADR-0021 (boot_multi_strategy_skeleton)） |

### SC4 多板 / 多用户泛化（框架参考实现）

| 编号 | 需求 | 判据 |
|---|---|---|
| R-IMG-3 | 镜像头契约 = **两工程共享的单一头文件**，版本化 | 两个独立工程 include 同一份；契约变更必须显式升版本（ADR-0021） |
| R-IMG-4 | 旧侧遇新侧结构**优雅拒绝**而非误读 | 未知结构版本 / 未知摘要算法 → 明确拒绝并可诊断 |
| R-IMG-5 | 摘要算法**可演进**（算法 ID + 固定尺寸预留区） | 由 CRC32 演进到 SHA-256+ECDSA 不动契约布局 |
| R-IMG-6 | 布局数值与契约常量**分离**（布局属工程配置，契约属代码） | 换板只改配置表，不改契约头 |
| R-SLOT-11 | 槽语义**平台无关**：上层只表达"槽 + 指针"，介质映射归板适配 | 槽位决策代码中不出现介质地址/寄存器（P-04） |
| R-SLOT-12 | 布局配置错误**显式报错**，不静默扩擦 | 非扇区对齐 / 越界布局在注册期或调用期显式失败 |

## 2. 失败模式矩阵

每一行 = "任意时刻掉电/失败"的一个站点，及其必须的恢复行为。

| 站点 | 落盘状态 | 恢复行为 | 归属需求 |
|---|---|---|---|
| 下载中断 | 目标槽半写 | 续传（接收侧记偏移）或重来；运行槽不受影响 | R-DL-3 / R-SLOT-1 |
| 写入中途掉电 | 同上 | 同上（未标 pending 前不换槽） | R-SLOT-2 |
| 标 pending 后掉电 | 决策已指向新槽 | 下次启动按 pending 试运行，计数推进 | R-SLOT-6/7 |
| 试运行中掉电 | 计数已落盘 | 计数 +1，达限自动回退 | R-SLOT-6/7 |
| 新镜像校验失败 | 无 | **不跳转**，进入可交互状态；不擦除、不复位循环 | R-DL-4 |
| 决策数据半写 | 另一份完好 | 用另一份（轮转天然回退） | R-SLOT-9 |
| 决策数据两份皆坏 | 无有效决策 | 冷启动路径：挑一个合法镜像启动；都不合法 → 停在可交互状态 | R-DL-1 / R-SLOT-9 |
| 回退目标也无效 | 无 | 停在可交互状态（**不写指向坏镜像的决策**） | R-SLOT-9 |
| 升级提交期掉电（非 direct 策略） | 提交进度已落盘 | 断点续做或安全回退 | R-SLOT-10 |

**共同约束**：任一站点掉电后，设备必须仍能被后门完整重新灌写（R-DL-1）——这是全矩阵的兜底。

## 3. 非功能需求

| 编号 | 需求 | 判据 |
|---|---|---|
| R-NFR-1 | bootloader **无动态内存**、启动路径确定性 | 静态链接产物无堆依赖；同输入启动路径行为一致 |
| R-NFR-2 | 面积**可观测**（构建后自动出 size 报告），预算内 | 首版预算 = 64K 参考值（ADR-0021）；实测余量 ≈ 2.5×（K-29） |
| R-NFR-3 | 校验**每次上电全量**，且耗时可接受 | 每次上电校验整个待启动镜像；不引入"校验一次 + 缓存"的削弱机制（K-29） |
| R-NFR-4 | 决策核**平台无关可测**（主机侧可运行） | 决策/解析/校验逻辑可在主机跑语料 |
| R-NFR-5 | 双工具链等价（GNU 与 armclang 链接布局一致） | 双工具链下槽偏移构建均产出可启动镜像 |
| R-NFR-6 | 可裁剪：bootloader 形态与 app 形态共用同一套框架原语 | bootloader 侧不因裁剪引入独立实现分支 |
| R-NFR-7 | 摘要算法**跨平台一致**（框架定义 canonical 变体，芯片后端负责映射） | 任一后端算出的摘要与 PC 工具侧一致（K-28） |

## 4. 由本框架的运行时形态推出的需求

以下两条不是生态通行结论，而是从"bootloader 与槽共享同一擦写域""bootloader 先于 OS 接管启动"这两个前提推导出来的。

### 4.1 自持擦写期的响应延迟

**前提**：bootloader 只写非活动槽；当非活动槽与 bootloader 同处一个擦写域时，擦/写该槽会阻塞执行流（跨擦写域时不会）。

- 下载会话期间，阻塞表现为**响应延迟**（最坏一次可达秒级），而非数据损坏——前提是传输采用**停等**（R-DL-7）。
- 若主机不守停等而流式发送，阻塞期间接收侧无服务会丢字节（接收侧每字单缓冲、无 FIFO）。

| 编号 | 需求 | 判据 |
|---|---|---|
| R-DL-7 | 传输为**停等**：每帧等响应再发下一帧 | 单帧未收到响应时发送侧不继续发送 |
| R-DL-8 | 超时参数**覆盖最坏擦除时间**（或擦除粒度受控） | 擦除型命令的等待窗口大于最大单次擦除耗时 |

### 4.2 跳转后的中断责任方

**前提**：bootloader 为关中断的确定性执行流，而 app 的复位入口与厂商初始化均不负责放开中断。

| 编号 | 需求 | 判据 |
|---|---|---|
| R-JMP-1 | 跳转前完成执行环境清理（中断面、系统时基、bootloader 用过的外设） | 跳转后到达 app 前的挂起中断不落到 app 的默认处理（K-27 动作清单） |
| R-JMP-2 | **中断放开的责任方在契约中定死**（bootloader 跳转前放开，或 app 早期统一放开——二者择一） | app 在既有启动流程下能正常收到中断 |
